# 交付索引

本目录按「业务挖掘 → 行业分析 → 流程设计 → 方案报价 → 实施验证」组织，
每份文件都标注了对应的需求事实编号（f00–f55），便于回溯依据。

## 二、阅读路径

**给决策者（顾明岚 / 傅景）**
1. `03-流程图/01-现状流程图.svg` —— 先看问题在哪个环节
2. `02-行业分析` 第一节「结论摘要」—— 99.9% 的口径问题
3. `04-方案与报价/报价单` 第一页 —— 钱和工期

**给业务骨干（唐映秋 / 林亦舟 / 叶书）**
1. `01-业务挖掘/业务需求发现报告` 第三节「六个岗位看到的问题」—— 对照自己的陈述
2. `03-流程图/02-数智化转型后流程图.svg` —— 哪些环节变了，哪些没变
3. `05-mvp/` 跑一遍，看差异清单是否覆盖自己遇到的场景

**给技术评审（秦芮）**
1. `04-方案与报价/解决方案设计` 第二、四、五章 —— 架构、数据模型、匹配策略
2. `05-mvp/recon/` 源码 —— 7 个模块，每个文件顶部都有设计说明
3. `05-mvp/tests/test_recon.py` —— 13 项约束测试

## 四、口径与免责

- **数据**：全部为合成样本，不含真实商户与交易。
- **需求**：来源于合成场景访谈，属待验证假设，覆盖率 36/36 不等于验收通过。
- **指标**：99.9% 为"已给出结论样本中的正确率"，分母与排除规则见行业分析第五节与设计方案第九章。
- **边界**：方案为只读旁路，不具备任何资金操作能力。

## 五、文档生成

`02-行业分析` 的 docx 与 `04-方案与报价` 的 xlsx 由脚本生成，可复现：

```bash
python tools/build_industry_docx.py   # 需要 python-docx
python tools/build_quote_xlsx.py      # 需要 openpyxl
```

流程图 SVG 为手工绘制的源文件，PNG 由 Chrome 无头模式按 2 倍分辨率导出。
